## September Change and Quality of Old Schemes

[table_layout.py](https://github.com/NattKh/CRIMSON-DESERT-SAVE-EDITOR-AND-GAME-MODS/blob/96e7f78fcb00d6cb5615171a7f359f0c2de5b114/CrimsonGameMods/table_layout.py) calls version **2.01.00** and translates `gamedata/binary__/client/bin/*.pabgb/.pabgh` to **`gamedata/binarystaticinfo__/bin/*.staticinfobody/.staticinfoheader`**. This also changes the internal archive path; Merely renaming the ending is not enough. The exact date 04.09.2026 is not proven by this file alone.

Stock records: The [April-Parser](https://github.com/NattKh/CrimsonDesertModdingTools/blob/1a9c3f10440713ee1b8f0bb88f66091376b433b5/parsers/storeinfo_parser.py) uses 105 bytes, the [September-Parser](https://github.com/NattKh/CRIMSON-DESERT-SAVE-EDITOR-AND-GAME-MODS/blob/96e7f78fcb00d6cb5615171a7f359f0c2de5b114/CrimsonGameMods/storeinfo_parser.py) 113 bytes. This supports **+8 bytes**, but does not prove the meaning, insertion point or validity for all variants. The new parser seeks header sizes heuristically. In addition, he reads `item_key` at stock offset `+0x1E`, while `swap_item` writes after `+0x22`. This inconsistency prohibits unchecked takeover. Historical price offsets are old `+2/+0x0A`, new `+0x06/+0x0E` (u64 buy/sell); None of these are released without build verification for Workbench.

The [extracted scheme](https://github.com/NattKh/CrimsonDesertModdingTools/blob/1a9c3f10440713ee1b8f0bb88f66091376b433b5/schemas/pabgb_complete_schema.json) contains field names, reader addresses and partly byte widths, but also `null`, composite blocks and conflicting type specifications. A `direct_12B` is a byte block and not a proven scalar. Memory addresses like `a2+112` are **not file offsets**. Many file offsets depend on previous strings and arrays. The universal dumper is not proof of complete parser coverage.

The index is also table-specific: CharacterInfo used in the historical parser `u16 count + (u32 key,u32 offset)`; RegionInfo and StoreInfo use `u16 count + (u16 key,u32 offset)`. Do not transfer the guide’s blanket index description to each table.

## Empirical error modes and consequences for B0

The [MODDING_GUIDE.md](https://github.com/NattKh/CRIMSON-DESERT-SAVE-EDITOR-AND-GAME-MODS/blob/96e7f78fcb00d6cb5615171a7f359f0c2de5b114/CrimsonGameMods/MODDING_GUIDE.md) documents April-2026 attempts. They are valuable regression tests, not warranties reproduced on the September build:

- Length changes require a recalculated header index including entry number. Otherwise, items can silently disappear or be read incorrectly.
- `iteminfo` and `equipslotinfo` had to be divided into separate overlay groups in the experiments; The same bytes in a common group changed equipment.
- Load numerical group names; Nonnumericals were silently ignored. Similar tables in several overlays are not merged field-by-field at runtime. B0 must merge semantically in advance and visibly resolve conflicts.
- Registry checksums must match the PAMT. Another manager can clean up unknown numerical groups. B0 must therefore not claim any foreign groups as its own.
- Patching count/string length/optional tags in isolation can destroy the stream; Absolute offsets become obsolete after inserts. Suspicious foreign patches at most reparse/diffen against their exactly known base, otherwise refuse.
- Serializer errors must not revert to obsolete bytes. Roundtrip alone does not prove game compatibility; Manual in-game tests remain necessary.

The old full path specification `gamedata/binary__/client/bin` in the guide is overtaken by `table_layout.py`. Also supposedly universal u16/u32 indices and fixed group areas have to be checked against current files. A blanket “dict edits always safe” from the guide is not a security guarantee.

Additional code finding in `buffs_v319.py` by line 7317: RegisterConditionSkillBuffData (tag 63) contains Weapon Equip Type conditions. On inappropriate non-weapons, the unattainable condition is intended to trigger endless loops during loading and heavy memory consumption. B11 requires a compatibility check before such passive effects are offered as secure templates.

For the current phase, only documentation and read-only research continue to apply. No overlay, registry, save or apply action was started from this research.
